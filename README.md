# 基于用户画像与矩阵分解的电影智能推荐平台设计与实现

一个用 **Python + Django** 写的电影推荐网站：用户注册登录后先选兴趣标签，可以浏览电影、给电影打分/收藏/评论，
平台用 **三种推荐算法** 给他推电影，并提供 **"我的画像"** 页面把观影口味可视化出来，
还有 **"打分专区"** 页面专门演示"先打分 → 再训练矩阵分解 → 出画像和推荐"这条完整链路。

> 本项目是课程大作业的完整可运行工程，开发语言 Python，单机即可部署运行，**运行时不依赖任何外部网络**。

## 二、三种推荐算法（这就是"用户画像 + 矩阵分解"的落点）

| 算法 | 文件 | 一句话原理 | 在界面上哪里能看到 |
| --- | --- | --- | --- |
| 基于用户的协同过滤 UserCF | `movie_it/recommend_movies.py` | 找到和你口味最像的人，把他们喜欢而你没看过的电影推给你 | 算法与接口 `/user_recommend/` 都保留，但**界面上已没有入口**（原来挂在首页右侧栏） |
| 基于物品的协同过滤 ItemCF | `movie_it/recommend_movies.py` | 找到和你喜欢的电影最相似的电影推给你 | 电影详情页"相关推荐" |
| **矩阵分解（隐语义模型）** | `movie_it/svd_recommend.py` | 把评分矩阵分解成"用户画像向量 × 电影画像向量"，补全你没评过的格子 | 顶部导航"矩阵分解推荐" |

### 矩阵分解是怎么做的（`movie_it/svd_recommend.py`）

把「用户-电影」评分矩阵 R（行=用户，列=电影，没评过的位置是 0）近似分解成：

```
R ≈ μ + b_u + b_i + X · W
```

- `X`（m×k）：**用户画像矩阵**，第 u 行就是用户 u 的 k 维"兴趣向量"
- `W`（k×n）：**电影画像矩阵**，第 i 列就是电影 i 的 k 维"特征向量"
- `μ`：全体平均分；`b_u` / `b_i`：用户偏置 / 电影偏置（有人天生给分高，有电影天生分高）

训练时只在"已知评分"的位置计算误差，用梯度下降让误差平方和最小，并加正则项防止过拟合
（偏置项按观测条数取平均后再更新，避免"评了几百部的用户"步长是"只评一部的用户"的上百倍而发散；
训练里还加了发散回退保护，万一学习率给大了就回退到上一轮参数）；
训练完成后用 `X · W` 补全没评过的位置，取预测分最高、用户没看过的电影推荐。

超参数（在 `svd_recommend.py` 顶部，改完重启即可）：`k=20, 学习率 0.01, 正则 0.05, 迭代 100 轮`。

### 算法效果怎么衡量

`evaluate_model()` 会把评分随机划分成训练集（80%）和测试集（20%），只用训练集训练，
再在测试集上算 **RMSE（均方根误差）/ MAE（平均绝对误差）**，并和一个"一律预测平均分"的基线对比。

在当前这份模拟数据上实测（6425 条训练 / 1607 条测试，可评价样本 1481 条）：

| 指标 | 矩阵分解模型 | 基线（一律预测平均分） |
| --- | --- | --- |
| RMSE（越小越好） | **0.7813** | 0.8225 |
| MAE（越小越好） | **0.5362** | — |

即误差比基线低约 5%。**注意这个数字依赖数据库里的评分数据**，所以第 八 节那批模拟评分的参数
（尤其是公式的截断幅度）会直接影响它；如果数据库是空的，这一页不会显示任何指标。

## 三、新用户上手：注册 → 选标签 → 看推荐

这是现在最主要的入口，专门解决"新账号没有任何数据、任何算法都算不出东西"的冷启动问题：

1. 注册并登录 → 自动进入 **「选择你喜欢的标签」** 页
2. 点选标签（选中会变成反色胶囊，再点一次取消）
3. 点"提交" → 直接跳到 **「根据你选的标签，为你推荐」** 页面：
   - 顶部列出你选中的兴趣标签
   - 下面 24 张电影卡片，按 **命中标签数 → 豆瓣评分** 排序
   - 每张卡片标出"命中 N 个标签 · 豆瓣 x.x 分"，为什么推这部一目了然
   - 底部三个按钮：去首页 / 去打分专区 / 看矩阵分解效果
4. 导航栏也有"**标签推荐**"入口，随时能再回来看

> 如果一部标签都没选就提交，会提示"请至少选择一个标签"，不会把你带到空页面。

### 打分专区（`/rate_movies/`，演示时最省事的入口）

1. 页面一次随机给出 **15 部**"有名气"（豆瓣评价人数最多）而且你还没评过的电影，每部后面配 1~5 分的单选框
2. 至少打 5 部，点"提交评分" → 后端把这批评分写进 `movie_rate` 表，
   同时按"标签累加 (mark - 3)"的规则更新 `movie_usertagprefer`
3. 提交后自动跳到结果页，**当场重新训练矩阵分解模型**，一次展示三样东西：
   - 你的**兴趣标签画像**（条形图，偏好值高的排前面）
   - 矩阵分解学出来的**画像向量**（20 维条形图，正值亮色、负值暗色）
   - **矩阵分解推荐 Top-12**（带模型预测评分）

页面上还有"再打一批电影""查看完整画像""矩阵分解推荐页"三个按钮，方便连续演示。

## 四、"我的画像"页面怎么算出来的

`movie_it/svd_recommend.py` + `movie/views.py` 的 `profile()` 视图（和打分专区共用 `_profile_bars()`）：

1. **行为统计**：评分数、平均打分、收藏数、评论数（来自 `movie_rate` / `movie_movie` / `movie_comment` 表）
2. **兴趣标签**：把用户评过分的电影的类型标签加权累加（打 4 分以上加分，打 1~2 分减分），
   再叠加 `movie_usertagprefer` 表里已有的标签偏好，得到"偏好值"排行 → 画成条形图
3. **画像向量**：直接取出矩阵分解训练出的用户隐向量 `X[u]`（20 维），画成条形图 ——
   这几根柱子就是"算法眼里的你"
4. **猜你喜欢**：用画像向量和所有电影向量算余弦相似度，取最相似的若干部电影
5. **常看导演 / 年代分布**：从评分记录里统计

## 八、关于数据（重要，答辩时容易被问）

- `db.sqlite3` 里的电影数据来自 `csv_data/`（豆瓣电影、Top250），是**真实电影信息**：
  影片 **2153** 部、标签 **24** 类、影片-标签关系 **5483** 条，海报 2153 张齐全。
- **当前数据库里没有任何评分数据**（已连账号一起清空）。
- 原项目自带的评分数据是 `random.randint(1,5)` 随机生成的（见 `populate_data/populate_user_rate.py`），
  和用户口味没有任何关系，在这种纯噪声数据上任何算法都赢不了"一律预测平均分"。
- 所以本项目新增了 `populate_data/populate_sim_ratings.py`：给每个用户生成一个**隐藏口味向量**，
  评分 = `3 + 1.7 × 口味匹配度 + 噪声`（1~5 分，保留一位小数），
  让矩阵分解能真的从评分里把"口味"学出来。
  **这是课程实验用的模拟数据，不是真实用户评分**；真实场景应该换成
  [MovieLens](https://grouplens.org/datasets/movielens/) 这类公开数据集。

想在答辩时展示矩阵分解的 RMSE/MAE 对比，先造数据（会同时创建一批模拟用户）：

```bat
:: 生成模拟评分（默认 400 个用户 × 每人 20 条，随机种子固定、结果可复现）
venv\Scripts\python.exe populate_data\populate_sim_ratings.py
venv\Scripts\python.exe populate_data\populate_sim_ratings.py --users 600 --per-user 25 --seed 2026
```

> 小提示：这批模拟数据里会有相当一部分评分被截断到 5.0，信号被压平，
> 所以矩阵分解的 RMSE 只比基线好约 5%，不会出现"大幅领先"的效果。
> 如果想让对比更好看，可以调 `populate_sim_ratings.py` 里的生成参数。

## 九、列表排序规则（都是从高到低）

| 页面 | 排序依据 | 卡片上显示的文字 |
| --- | --- | --- |
| 首页 · 热度排序（默认） | 浏览量，从多到少 | `xx 次浏览 · 豆瓣 x.x 分` |
| 首页 · 评分排序 | 用户平均打分，从高到低 | `平均 x.xx 分 · x 人评价` |
| 首页 · 收藏排序 | 收藏人数，从多到少 | `x 人收藏` |
| 首页 · 时间排序 | 上映时间，从新到旧 | `2020-01-10` |
| 标签页 / 搜索结果 | **豆瓣评分**，从高到低 | `豆瓣 x.x 分 · x 人评价` |
| 收藏最多 / 评分最多 / 浏览最多 | 对应指标，从多到少 | `x 人收藏` / `x 人评分` / `x 次浏览` |
| 标签推荐页 | 命中标签数 → 豆瓣评分 | `命中 N 个标签 · 豆瓣 x.x 分` |

> 每个卡片下面都会把**当前排序依据的数值**显示出来（`views.py` 里的 `add_sort_text()` 干这件事），
> 所以列表是从高到低排的一眼就能看出来，答辩演示时比较直观。

## 十、常见问题

| 现象 | 原因 / 解决 |
| --- | --- |
| 登录时提示账号不存在 | 数据库已清空所有账号，请先点"注册"新建一个 |
| `ModuleNotFoundError: No module named 'movierecomend'` | 要在**项目根目录**（有 `manage.py` 的那层）执行命令 |
| 端口 8000 被占用 | 换端口：`venv\Scripts\python.exe manage.py runserver 127.0.0.1:8001` |
| 改了 CSS，浏览器里看不到变化 | 样式表带了 `?v=` 版本号，把它改一个数（`base.html` 里）就能强制刷新；或按 Ctrl+F5 |
| 矩阵分解页 / 打分专区结果页第一次打开慢（1~3 秒） | 模型要现场训练，训练结果缓存 10 分钟；数据量越大越慢，属正常 |
| 矩阵分解页不显示 RMSE / MAE | 库里评分不足 10 条时模型不训练，页面会自动隐藏指标区 |
| 推荐结果为空 | 该账号还没有评分记录，去 **标签推荐** 或 **打分专区** 即可 |
| 打分专区提交后提示"没有记录到新的评分" | 一部电影的分都没勾，回去至少勾 5 部再提交 |
| 电影详情页点"豆瓣搜索"等按钮 | 是跳到正规平台按片名搜索的结果页，不是直接播放页（本项目不提供盗版资源） |
| 想换回原来的配色 | 删掉 `base.html` 里引用 `apple-theme.css` 那一行即可整体回退（原主题代码都还在） |
| 想让某个排序反过来（从低到高） | 排序逻辑在 `movie/views.py` 的 `index` / `one_tag` / `search` 里，把 `order_by('-num')` 前面的 `-` 去掉就是升序 |

## 十二、项目来源与改造说明

- 网站底座：[aql123/2021movie](https://github.com/aql123/2021movie)（Django + SQLite，自带电影数据、海报、UserCF/ItemCF）
- 矩阵分解算法：参考 [panlongpl/movieRcommend](https://github.com/panlongpl/movieRcommend) 的 `svdrecommend.py`
  思路，重写为带偏置的隐语义模型（Bias-MF），并接入本项目的数据库与页面
- 本项目在底座上的改造：

  1. 新增 `movie_it/svd_recommend.py`（矩阵分解 + 模型评估 + 标签画像 + 画像向量）
  2. 新增四个页面及对应视图与路由：`/svd_recommend/`（矩阵分解推荐）、`/profile/`（我的画像）、
     `/rate_movies/`（打分专区）、`/tag_recommend/`（标签推荐），并在导航栏加了入口
  3. 新增 `populate_data/populate_sim_ratings.py`（有规律的模拟评分数据）
  4. 技术栈升到 Python 3.9 + Django 3.2.25（原项目 Django 2.2 已停止维护），
     修掉模板 `staticfiles` 标签等兼容问题，并处理了 migrations 状态不一致
  5. 重写 `requirements.txt`（原版把爬虫依赖也写进去了，运行其实不需要）
  6. 电影详情页原来"前往观看"跳转的第三方小网站（`www.idybee.com`，域名已不可靠、会跳到可疑页面）
     换成 **豆瓣搜索 + 爱奇艺/腾讯视频/优酷/哔哩哔哩的按片名搜索结果页**（正规平台，只搜索不提供盗版资源）
  7. 前端整体改版成 **Apple 官网风格的深色主题**（内容与功能不变）：
     - **默认深色模式**：纯黑底 `#000`、白色主文字 `#f5f5f7`、次要文字灰 `#86868b`，全站只用黑白灰
     - **顶部状态栏是黑色毛玻璃**：`rgba(22,22,23,.72)` + `backdrop-filter: blur(20px) saturate(180%)`，
       吸顶显示；卡片、面板、弹窗同样是半透明磨砂材质 + 18px 大圆角 + 1px 发丝边框
     - **胶囊按钮**：`border-radius: 980px`，主按钮白底黑字、次要按钮磨砂灰；
       hover 有底色、按下去有 `scale(.96)` 的按压反馈，卡片 hover 会轻微上浮
     - **深浅色可切换**：导航最右侧的"◐ 浅色 / ◑ 深色"胶囊按钮切换，选择记在 `localStorage`
     - **字体**：内置 Inter（`static/fonts/inter-{400,500,600}.woff2`，本地文件、不依赖外网 CDN）
     - **首页 Hero 首屏**：大标题"电影推荐系统" + 副标题 + 两颗胶囊按钮，只挂在首页
       （`views.py` 的 `index` 传 `hero=True`，模板里用 `{% if hero %}` 包起来）
  8. **全站外部资源本地化**：原来登录页/注册页从 `cdn.bootcss.com` 拉 bootstrap、jQuery、Font Awesome
     （该 CDN 已停止服务），`base.html` 从 `stackpath.bootstrapcdn.com` 拉 Font Awesome（同样已下线），
     现在全部换成项目内 `static/` 下的本地文件，首页不再请求任何外部域名，页面打开速度恢复正常
  9. **删除右侧栏**：原来每个页面右侧有"最近更新"和"基于用户推荐电影"两块。
     后者与"基于用户画像推荐"这条主线无关，两块都已移除，主内容区改为占满整宽
     （UserCF 的算法与 `/user_recommend/` 接口仍保留在代码里）
  10. **新增"标签推荐"页**：选完标签直接给一屏按标签命中的电影，解决新用户冷启动的展示问题
  11. 修复 `/search/` 在从未搜索过时直接访问会 500 的问题
  12. 清空了数据库里所有历史账号与评分数据，只保留影片、标签和后台管理员账号
